# 白名单失效修复记录（2026-10）

## 现象

用户反馈：游龙工具会把无病毒的应用当成病毒拦截；把应用加入白名单后**没有效果**，
还是会拦截白名单里的（弹全屏拦截窗、"正在拦截"Toast、拦截历史、"请尽快卸载"通知，
超级模式下甚至直接 `am force-stop` 杀掉白名单应用）。

## 根因（共 6 处）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `ProtectService.triggerVolumeRescue()` / 摇一摇处理器 / 日常模式分支 | 白名单应用**照样弹救援窗**（旧设计"窗口照弹但不动应用"）。误触音量键/摇一摇时，白名单应用被全屏拦截窗盖住 + Toast + 拦截历史 + 循环卸载通知 —— 体验上就是"白名单没效果" |
| 2 | `ProtectService.showWarnOverlay()` 超级拦截 `doForceStop` | 5 秒倒计时后直接 `am force-stop pkgF`，**没有白名单检查**（ShieldWarnActivity 同路径有检查，唯独覆盖层路径漏了）→ 白名单应用被杀 |
| 3 | `ShieldWarnActivity.isProtectedApp()` | 只读 `whitelist_pkgs` 原始串，**漏掉内置默认信任包**（微信/QQ/支付宝/拼多多）与历史信任包（com.larus.nova / com.smile.gifmaker）→ 音量键救援 7 秒倒计时后对微信等直接拉起系统卸载框 |
| 4 | `ShieldWarnActivity.addToWhitelist()` | 用 `raw.contains(pkg)` **子串匹配**去重：新增包名是已有条目子串时（如已有 `com.a.bb` 再加 `com.a.b`）被静默跳过，"信任此应用"没生效 |
| 5 | `NotifyUninstallReceiver` | 通知栏"卸载软件"按钮不校验白名单，滞留的救援通知可以卸载白名单应用 |
| 6 | `BatchCleanupActivity.doBatchUninstall()` | 批量清除页不区分白名单，一键清除连白名单应用一起拉卸载框 |

## 修复

- **`WhitelistActivity`** 新增统一判定入口：`LEGACY_TRUSTED_PKGS`（历史信任包）与
  `isWhitelisted(Context, String)`（内置默认 + 历史 + 用户自定义，按条目**精确**匹配）。
  所有拦截/卸载入口共用，杜绝"某处漏检查"的不一致。
- **逃生路径（音量键/摇一摇/日常模式）**：前台是白名单应用时**不再弹任何拦截窗**，
  只给一条轻量 Toast（"前台应用在白名单中，已跳过拦截"）+ 轨迹日志。逃生通道本身不受影响。
- **`warnPopup()` 顶部终极保险**：白名单应用一律不弹窗、不写拦截历史（纵深防御，覆盖未来新增调用方）。
  逃生路径使用**实时 SharedPreferences 判定**（而非 4 秒一刷的缓存），
  避免"刚加完白名单就误触逃生"因缓存滞后继续拦截。
- **超级拦截覆盖层**：`doForceStop` 前增加 `isProtectedFinalPkg` 保护检查（与 ShieldWarnActivity/极强模式对齐）。
- **`ShieldWarnActivity.isProtectedApp`**：改用 `WhitelistActivity.isWhitelisted` 统一判定（补上内置/历史信任包）。
- **`addToWhitelist`**：按条目精确去重，修复子串误判；占位串（"未知应用"）不写入。
- **`NotifyUninstallReceiver` / `BatchCleanupActivity`**：执行卸载前先校验受保护/白名单，命中则跳过并提示。

## 已确认无需改动的路径

无障碍前台检测、新装包检测、黑白名单巡检、病毒库检测与批量卸载、终结/极强模式的
逐应用过滤、`executeUninstallOverlay`/`showFreezeAsk`/`executeDisableOverlay` 的终极保险——
这些路径原本就在调用前检查了白名单。
